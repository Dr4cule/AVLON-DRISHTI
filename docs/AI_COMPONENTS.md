# AI components — inspectable, no black boxes

> **AI recommends. The deterministic simulation verifies. The human decides.**
> Nothing below touches ground truth, ROE evaluation, scoring, or replay.
> The authoritative path is unchanged: client actions → server replay →
> server scoring → stored report.

## AI architecture

```text
                AVLON DRISHTI
                      │
            ┌─────────┴─────────┐
            │ Deterministic     │  ground truth · state · ROE · scoring
            │ Simulation Core   │  events · replay verification
            └─────────┬─────────┘
                      │ synthetic sensor data
      ┌───────────────┼────────────────┐
      ▼               ▼                ▼
AI Threat        AI Skill Model   AI Scenario
Assessment       / Adaptation     Intelligence
(advisory)       (Beta skills)    (challenge → generator)
      │               │                │
      └───────────────┼────────────────┘
                      ▼
               Trainee decision → scoring → AAR → history → AI
```

## 1. Threat model (`sim-core/threat/`)

- **Inputs:** 15 features from trainee-visible track data only (4 sensor
  confidences, range, speed, altitude estimate, heading change, closing rate,
  track stability, sensor agreement, degradation share, observation time,
  environmental noise, IFF presence). See `features.ts`.
- **Outputs:** `ThreatAssessment` — predicted class, confidence, normalized
  probabilities, uncertainty (1 − max), and per-feature evidence
  (see `model.ts`).
- **Model:** multinomial logistic regression (softmax), 15 → 6 classes
  (`bird`, `balloon`, `friendly_uav`, `unknown_uav`, `hostile_like_uav`,
  `clutter`), pure TypeScript, zero dependencies, few-KB JSON weights.
- **Training data:** labeled track snapshots generated headlessly by the sim
  itself (`npm run train:threat`, config + seed committed). Tracks younger than
  6 s or with fewer than 2 fresh sensor readings are labeled `unknown_uav` —
  insufficient evidence must mean "unknown". Raw data is never written to disk.
- **Why not ONNX:** the priority list (small → fast → CPU → explainable →
  offline) favors exact linear attributions over a WASM runtime.
- **Why no MLP:** an MLP was not built or benchmarked. The project deliberately
  retained the simpler softmax model because it already satisfied the required
  determinism, CPU-only/offline deployment, tiny footprint, and exact
  feature-attribution constraints, while the interaction benchmark did not meet
  the predefined improvement threshold.
- **Metrics:** see `docs/AI_THREAT_REPORT.md` (regenerated by training).
- **Determinism:** fixed weights + fixed features = bit-identical output.
  Retraining with the same seed reproduces byte-identical weights (tested).
- **Validation design:** the train/calibration/test split is grouped by
  scenario ID (70/10/20) — validation consists entirely of snapshots from
  simulations absent from training, i.e. generalization to *unseen simulated
  scenarios*. Reported alongside majority and rule-based baselines, macro and
  balanced metrics, stress subsets, scenario-level and established-track
  accuracy, and a hostile-vs-non-hostile view.
- **Calibration:** temperature scaling fitted on the calibration split only
  (never the reported test split). The UI number is therefore called
  **MODEL CONFIDENCE**: the model's own probability estimate, validated to
  track observed accuracy within the reported ECE — not a physical probability.
- **Leakage audit:** the extractor consumes only trainee-visible track and
  scenario fields (a test fails the build if ground-truth fields ever appear
  above the labeling function); ground truth enters solely through training
  labels, which is the entire point of supervised training.

## 2. Adaptive model (`sim-core/adaptive.ts`)

- Bayesian Beta(a,b) per skill dimension, init 2/2. Success (≥70,
  non-provisional) adds tag-weight `0.2+tag/5` to a, else to b.
  Mean a/(a+b), uncertainty 1/(a+b). Synthetic/provisional excluded.
- Persisted to `skill_state` on every finished session; served with a
  `persisted` flag (recomputed otherwise).
- **Explanation upgrade:** `detectPatterns` (`sim-core/threat/challenge.ts`)
  derives named patterns from recorded history only — recent accuracy slides,
  degraded-sensor-correlated errors, low-agreement classification errors found
  by replaying mistake ticks, clean-condition contrast, night errors.
- Surfaced as **AI TRAINING ANALYSIS** with uncertainty, calibration table,
  detected patterns, and per-session skill deltas ("61% → 74%").

## 3. Scenario intelligence (`sim-core/threat/challenge.ts` + generator)

- Weakest skill → **challenge profile** (night, terrain, IR degradation,
  sensor conflict, contact load, ambiguity) → compiled onto the generator's
  existing knobs (`difficulty_profile`, `focus`, `constraints`).
- **Adversary emphasis:** a deterministic weakness→behavior map
  (`saturation` for swarm weakness, `decoy_and_strike` for distractors, …)
  passed as `behaviorBias`; unknown entries are rejected, empty intersections
  fall back to the full list. These are abstract gameplay doctrine labels,
  not real-world tactics.
- The baseline-feasibility gate, schema validation, and fingerprint diversity
  remain mandatory — the AI can only choose among fair exercises, and the UI
  labels generation as **AI SCENARIO GENERATION · BASELINE-CHECKED**.

## 4. AAR AI analysis (`sim-core/threat/analysis.ts` + `AiAnalysis`)

- Picks the first critical (else first) recorded mistake, replays to its tick,
  reconstructs what the advisory model estimated then, and renders
  opportunity → what happened (scorer's words, reused) → sensor evidence →
  model view → lesson template → practice link.
- Returns nulls (rendered as "no training opportunity") when the scorer
  recorded nothing or the track cannot be reconstructed. Nothing is invented.

## Explainability

- Threat evidence is *exact* linear attribution (weights × features), verified
  by test — not an approximation.
- Adaptive rationales, patterns, and lessons are templates filled from
  structured metrics, never LLM output.
- UI carries a consistent AI visual language: AI THREAT ASSESSMENT /
  AI TRAINING ANALYSIS / AI RECOMMENDATION / AI SCENARIO GENERATION, each
  paired with HUMAN DECIDES or advisory disclaimers.

## Canonical terminology

Use: synthetic observations · held-out simulated scenarios · model confidence
(the calibrated model probability defined above) · advisory · human decision ·
training heuristic · practice exercise · deterministic replay ·
baseline-feasibility gate. The model learns the simulator's evidence patterns;
it is not validated for real sensor transfer.

## Claims and evidence (auditable)

| Claim | Evidence |
|---|---|
| Threat model is deterministic | `model.ts` + retraining determinism test |
| No ground-truth feature leakage | `features.ts` separation + leakage guard test |
| Test scenarios are unseen during training | grouped split + overlap guard that aborts training |
| Calibration uses separate data | calibration split + ECE evaluated on test only |
| AI does not affect scoring | scorer remains deterministic and server-authoritative |
| Generated scenarios remain fair | baseline-feasibility gate on every generation |
| Replay is reproducible | replay verification + E2E judge path |

## Limitations (state these on stage)

- Sensor models are fictional gameplay abstractions; the threat model learned
  *our* evidence patterns and cannot transfer to real sensors.
- Generated training data is synthetic; known-hard pairs (bird/balloon,
  clutter precision) are documented in the training report, not hidden.
- AI predictions are advisory; scores are practice heuristics, not readiness
  certification. The system is not an operational threat-assessment platform.

## Tests

`tests/threat.test.ts` (extraction, model contract, determinism, invalid
inputs, hostile distribution, training determinism), `tests/analysis.test.ts`
(explanation from evidence, empty fallback, no fabrication),
`tests/challenge.test.ts` (patterns, profile mapping, fairness preserved,
tactics, bias validation), plus backend recommend/persistence coverage.
